# 06 — Verification

**Reads:** Accepted decisions, revision record if any, and the target product.

**Produces:** `results.md` with fresh screenshots, affected task checks, accessibility or functional results, reviewer reassessment where appropriate, and unresolved issues. For a visual council run, also record the art director’s comparison of matched build captures with the selected design.

**Check before handoff:** If the handoff must use disposable data, verify that the ordinary launch path opens the disposable profile before using tools that can start or reopen the app. A test harness’s profile override covers only that launch. State the exact level of evidence. Automated checks, synthetic interaction, physical-device checks, real-user testing, and subjective review are different. In review-only mode, report what was inspected and what remains to validate; do not imply a revision was verified.
